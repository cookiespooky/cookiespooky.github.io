# Маршрут: идея → проверка спроса → первый MVP

Цель маршрута — провести пользователя от идеи продукта к минимальной проверке спроса без лишней разработки.

## Основной путь

[[startup-hypothesis]] → [[demand-validation]] → [[traction-signal]] → [[mvp]] → [[product-scope]] → [[lead-startup-diagnostic]]

## Альтернативные ветки

- [[build-trap]] → [[system-before-sales]] → [[concierge-mvp]] → [[lead-startup-diagnostic]]
- [[saas]] → [[product-market-fit]] → [[demand-validation]] → [[lead-startup-diagnostic]]
- [[founder-chaos]] → [[founder-decision-map]] → [[product-choice]] → [[lead-product-choice]]
- [[landing-page-test]] → [[offer]] → [[marketing-os]] → [[lead-marketing-diagnostic]]

## Главное действие

[[lead-startup-diagnostic]] — когда нужно сформулировать гипотезу, выбрать минимальный тест, определить сигнал спроса и сузить первую версию продукта.

MVP может быть ручным, no-code, лендингом, консультацией, concierge-форматом, техническим прототипом или AI-инструментом. AI — только частный случай, если он действительно нужен для проверки.
