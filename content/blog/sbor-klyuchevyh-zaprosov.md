Половина инструкций по Wordstat API ведёт через API Директа с заявкой и обращением в поддержку — это устаревший путь. Проверено в сентябре 2026 года по документации: цены и квоты меняются, перед работой сверьтесь с актуальной версией. Зачем частоты нужны сайту услуг — в статьях [«Страницы под города»](/blog/stranicy-pod-goroda/) и [«AI SEO для сайта услуг»](/blog/ai-seo-dlya-sayta-uslug/).

Wordstat API живёт в Yandex Cloud, в Search API. Главное ограничение при сборе частотности запросов — не цена, а квота в сто запросов в час.

## Wordstat API переехал в Yandex Cloud Search API

Русская и английская документация расходятся: английская описывает заявку и обращение в поддержку Директа с `ClientId` — это старый путь. Актуальный API — в Yandex Cloud, в составе Search API:

```
POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests
Authorization: Bearer <IAM-токен>
```

Аутентификация — сервисный аккаунт Yandex Cloud с ролью `search-api.webSearch.user`, без OAuth-приложения. Проверка — выдать роль, взять токен, сделать один запрос: пришёл ответ — заявка не нужна.

## Методы Wordstat API

| Метод | Что даёт | Тарифицируется |
|---|---|---|
| `GetTop` | топ запросов, содержащих ваши слова, за 30 дней | да |
| `GetDynamics` | частота по месяцам, неделям, дням | да |
| `GetRegionsDistribution` | распределение по регионам | да, дороже |
| `GetRegionsTree` | коды регионов | нет |

Запрос `GetTop` принимает фразу до 400 символов и до 40 слов, число результатов, список регионов и типы устройств. В ответе — общее количество, массив результатов и похожие запросы.

## Сколько стоит собрать частоты

Двадцать рублей за тысячу запросов для `GetTop` и `GetDynamics`, пятьдесят — для распределения по регионам. Бесплатного объёма у Search API нет: нужен платёжный аккаунт с положительным балансом.

Реальная работа — тринадцать групп, полсотни исходных фраз:

| Что | Запросов | Стоимость |
|---|---|---|
| `GetTop` по всем фразам | ~50 | 1 ₽ |
| `GetDynamics` по выжившим группам | ~13 | 0,3 ₽ |
| `GetRegionsTree` | 1 | 0 ₽ |

Три рубля; программа на порядок шире — около пятидесяти. **Цена — не ограничение.**

## Настоящее ограничение — квота

`GetTop` разрешает десять запросов в секунду, но **всего сто запросов в час**.

Это определяет устройство сборщика:

- **Ограничитель скорости обязателен** — в потолок легко упереться на ровном месте.
- **Возобновляемость важнее скорости.** Упасть на восьмидесятом запросе — час ожидания, поэтому состояние сохраняется после каждого ответа.
- **Пакетность.** Один `GetTop` разворачивает целую группу — до двух тысяч формулировок с частотами, — поэтому исходных фраз мало и они удачные.

Те же три требования стоят в [сборщике заказов с бирж](/cases/order-flow/) и [сборе тендерных публикаций](/cases/trade-radar/): внешний источник с лимитами и прогресс, который нельзя потерять. И ещё расхождение: справка по лимитам называет максимум 250 результатов, описание метода — 2000; проверять на практике.

## По какому числу приоритизировать запросы

В ответе два числа, и путать их дорого.

- `totalCount` — сколько всего запросов содержат эти слова. Это широкий потолок. Приоритизировать по нему — та же ошибка, что оценивать спрос по широкому соответствию в веб-интерфейсе.
- `results[].count` — частота **конкретной формулировки**, как её действительно набирают люди. Приоритизировать надо по ней.

Это лучше операторной арифметики: вместо оценки — фактическое распределение запросов.

## Операторы точной формы доступны только в веб-интерфейсе

Операторы — кавычки, восклицательный знак, скобки, плюс — в документации API не описаны, а веб-интерфейс `wordstat.yandex.ru` их поддерживает бесплатно. Поэтому **на первой волне API может быть не нужен**: полсотни фраз руками — пара часов, ноль рублей и точность, которой у API нет. API окупается, когда сбор становится регулярным; семантику для одного сайта один раз — собирайте в веб-интерфейсе.

## Что из этого следует: что делать с собранными частотами

Сами по себе числа бесполезны. Нужны две вещи.

**Реестр** «группа запросов → адрес страницы → статус». Он не даёт написать вторую страницу под тот же интент — самую частую и дорогую ошибку. Одна группа — один адрес.

**Расстояние до денег.** Частый запрос может никогда не приводить к оплаченной работе. Я оцениваю группу по шагам от запроса до заказа и всё, что дальше трёх, не пишу. Дальше группы становятся структурой сайта — [страницами под сочетания](/blog/stranicy-pod-goroda/). Если делать из этого продукт — условия использования ограничивают хранение и перепродажу данных Wordstat.
