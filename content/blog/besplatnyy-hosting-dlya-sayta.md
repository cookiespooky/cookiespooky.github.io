Статический сайт — набор готовых файлов: ни сервера приложений, ни базы данных, страницу достаточно отдать. Поэтому его действительно можно разместить бесплатно, без пробного периода. Как на таком сайте принимать заявки — в статье [«Заявки с сайта без бэкенда»](/blog/zayavki-s-sayta/), как принимать оплату — [«Оплата на сайте без интернет-магазина»](/blog/oplata-na-sayte-bez-magazina/), где бесплатно держать бота — [отдельно](/blog/gde-hostit-telegram-bota/).

Бесплатный хостинг для сайта компании есть, но не для любого сайта: у площадок есть лимиты, а GitHub Pages прямо запрещает коммерцию.

## Лимиты бесплатных площадок

На примере GitHub Pages, где живёт этот сайт; цифры — из документации GitHub:

| Ограничение | Значение |
|---|---|
| Размер опубликованного сайта | не больше 1 ГБ |
| Рекомендованный размер репозитория | 1 ГБ |
| Трафик | мягкий лимит 100 ГБ в месяц |
| Частота сборок | мягкий лимит 10 в час |

«Мягкий» — не отключат на 101-м гигабайте, но при систематическом превышении свяжутся. Сайт компании на два-три десятка страниц этих лимитов не заметит: 100 ГБ — сотни тысяч просмотров. Лимит сборок не действует, если публикация идёт своим сценарием GitHub Actions.

## Сайт на GitHub Pages: запрет на коммерцию

Документация GitHub прямо говорит: Pages не предназначен и не разрешён к использованию в качестве бесплатного хостинга для ведения онлайн-бизнеса, интернет-магазина или любого сайта, направленного преимущественно на совершение коммерческих сделок либо предоставление коммерческого программного обеспечения как услуги.

Читать буквально — по тому, что сайт делает:

- **Интернет-магазин с корзиной и оплатой** — нельзя. Это ровно тот случай, который назван.
- **Сайт-визитка, каталог услуг, портфолио, документация, блог** — можно. Он рассказывает о компании, а сделка происходит в другом месте: в переписке, по телефону, в счёте.

Граница — совершается ли на сайте транзакция, а не есть ли у владельца ИНН. Сомневаетесь — берите платный хостинг за несколько сотен рублей в месяц: перенос статики занимает пару минут.

## Чего статический сайт не умеет без сервера

Второе ограничение не зависит от площадки: на статическом хостинге не выполняется ваш код —

- нет PHP, Python и подобного на стороне сервера;
- нет базы данных;
- нет обработки форм — некому принять отправленные данные;
- нет личных кабинетов и авторизации;
- нет настоящих редиректов 301 и ответов 410, только 404 и переадресация скриптом.

При переезде со старого сайта последний пункт решают заранее: без 301 накопленные адреса аккуратно не перенести.

## Как это выглядит на живых проектах

[Демонстрационный каталог услуг](/cases/gorod-katalog/) — около двухсот страниц из таблицы «услуги × города», ноль рублей в месяц: страницы открываются мгновенно, ломаться и взламывать нечего.

[Сайт «Утилитсервиса»](/cases/utilitservis/) — контрпример: заявки нужно было принимать на свою почту. Сайт остался статическим, но переехал на обычный хостинг, и весь его бэкенд — один файл-обработчик формы. Выбор не «статика или сервер», а «сколько серверного кода нужно», и часто ответ — один файл.

## Что из этого следует: куда выложить статический сайт

- **Нет форм, нет оплаты, нужен сайт-визитка или каталог** — бесплатный статический хостинг, свой домен, и годами не вспоминать.
- **Нужна форма заявки на своей стороне** — сторонний сервис форм или дешёвый хостинг с одним обработчиком ([варианты](/blog/zayavki-s-sayta/)).
- **Магазин с корзиной и оплатой** — платный хостинг сразу, без вариантов.

Во всех трёх случаях сайт может оставаться статическим: [движок](/cases/notepub/), который собирает его из текстов, не зависит от того, где лежат файлы.
