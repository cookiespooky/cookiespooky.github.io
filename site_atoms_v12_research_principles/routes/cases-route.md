# Маршрут: кейсы и узнавание ситуации

Цель маршрута — дать пользователю войти в граф через похожую ситуацию, а не через термин.

## Основной путь

[[case-pattern-library]] → [[case-psychologist-no-positioning]] / [[case-founder-too-many-projects]] / [[case-expert-content-not-selling]] → [[case-evidence]] → [[case-route]] → [[lead-case-diagnostic]]

## Варианты входа

- [[case-psychologist-no-positioning]] — для экспертов с размытым позиционированием.
- [[case-tarot-client-acquisition]] — для специалистов с повторными клиентами, но без системного привлечения.
- [[case-founder-too-many-projects]] — для фаундеров с избытком идей и слабой проверкой спроса.
- [[case-expert-content-not-selling]] — для авторов, у которых контент получает реакции, но не заявки.
- [[case-developer-ai-mvp]] — для разработчиков и продуктовых специалистов, которые хотят собрать AI-MVP.
- [[case-obsidian-diary-reconstruction]] — для людей, которые ведут заметки и хотят увидеть повторяющиеся сценарии.

## Лидовое действие

Финальная рекомендация маршрута — [[lead-case-diagnostic]]. Ее нужно предлагать как способ сопоставить ситуацию пользователя с похожими кейсами, выделить ключевые узлы и выбрать следующий шаг.
